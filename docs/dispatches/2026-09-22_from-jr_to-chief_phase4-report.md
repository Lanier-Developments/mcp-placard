## Flag-backs, answered

### 1. Canonical JSON does not make SARIF line regions meaningless

Placard's manifests are rendered as indented canonical JSON — sorted keys, two-space
indent, one key or array element per line — so every JSON Pointer segment sits on
its own line. `report/locate.py` walks the rendered text with an indentation stack
and returns the line where a pointer's value begins; `tests/test_report_locate.py`
pins nine pointers against the real mock manifest, container pointers, escaped
segments, and unresolvable ones. SARIF `physicalLocation` carries the committed
baseline path with `uriBaseId: %SRCROOT%` and a `region.startLine`; the pointer is a
`logicalLocation`. No format decision was needed.

### 2. Environment isolation broke nothing mainstream

Under `PATH` + temporary `HOME` + redirected caches + nothing else, all eleven real
servers scanned: filesystem, memory, everything, sequential-thinking, github,
playwright (`npx`); fetch, git, time (`uvx`); deepwiki, context7 (HTTP). Run through
`placard check` with a scratch `placard.toml`, so it exercised the real path, not a
test harness. Nothing reached for the real home.

One SDK fact forced a design choice worth knowing: the MCP SDK merges its own
inherited allowlist (`HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `PATH`) *under* any
environment it is given, so passing an environment to it cannot withhold those.
Placard therefore launches through `/usr/bin/env -i VAR=… command args`, which
clears everything first. The env-dump mock server confirms the child sees exactly
the isolated set plus the named variables — and that `HOME` is a fresh
`placard-home-*` directory, gone after the launch, different between launches. POSIX
only; there is no `env -i` on Windows, and the isolation there falls back to the
SDK's allowlist. Stated in `transport/stdio.py` and the threat model.

### 3. `--require-hashes` is workable in a composite action — and one step stronger

`requirements/action.txt` is generated by `uv pip compile --generate-hashes
--universal` and carries every distribution hash for every platform: 44 packages,
283 hash lines for `pydantic-core` alone, so a lock generated on a Mac installs
correctly on `ubuntu-latest` (your condition on ruling 1). The build backend
(`hatchling`) is pinned in the same file, and Placard is installed from the action's
own checkout with `--no-deps --no-build-isolation`, so nothing unpinned is fetched
for the build either. Proven locally in a clean venv on macOS, and the dogfood job
proves it on Linux. `scripts/lock_action_requirements.sh` regenerates the file.

### `check` and bit 16 (go memo, ruling 2)

`placard check` is the command the action wraps and the reason it works from GitLab
or anything else. Exit status is the OR of every server's bits, plus 16 when any
configured server could not be scanned; a tampered baseline also counts as
incomplete, since a gate that cannot trust its baseline is not a gate. A server with
no baseline yet is reported with a full-manifest report and sets no bit. `--fail-on`
does not change the exit status; it decides the `fail` boolean in `--outputs`, which
is what the action gates on. The routing acceptance case — prompt change,
`fail-on: escalation,injection` — passes with `prompt: true` and `fail: false`, and
the same run under the default `fail-on` fails. That test is named for what it
proves.

### The 3.2 correction

Own-name exemption: whole declared name, or its final path segment, generic tokens
(`mcp`, `server`, `servers`, `tools`) stripped, never arbitrary tokens.
`jira-slack-github-bridge` now exempts nothing but itself; `mcp-servers/everything`
still exempts "Everything Server"; `Playwright` still exempts "the Playwright server
process". Synthetic sample `syn-cross-scope-7` carries the hostile name. Ruleset 3.2,
shipped with 0.4.0 rather than as 0.3.2.

## Interpretations made in this phase, for overruling

- **`header_env` and `env` are separate keys.** The brief's `header_env` names HTTP
  request headers; a stdio server that needs a variable to start (the GitHub server's
  `GITHUB_PERSONAL_ACCESS_TOKEN`) needs the variable, not a header. Both are named by
  environment variable and neither value is stored.
- **`check` treats a baseline that fails `verify` as incomplete** rather than as a
  finding. There is no category for "the approval record was tampered with," and 16
  is the bit that means "this server was not gated."
- **Full-manifest SARIF carries only injection and chain findings.** Per-tool tiers
  are a table in the Markdown, not alerts; forty R1 alerts per server would be noise
  with a name attached.
- **`escape_excerpt` no longer escapes `-`, `.`, `+`, `(`, `)`, `{`, `}`.** They are
  Markdown-significant only at line start, excerpts are only ever inline, and
  `placard\-mock` in a title read badly. `<`, `>`, `[`, `]`, backtick, `*`, `_`, `#`,
  `|`, `~`, `!`, and backslash are still escaped; the inert-rendering tests cover
  `<IMPORTANT>`, `<!-- -->`, `[click](http://x)`, and a backtick that would close a
  code span.
